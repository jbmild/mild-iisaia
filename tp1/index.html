Diplomatura en desarrollo de aplicaciones utilizando inteligencia artificial

Introducción a la ingeniería de software asistida por IA

En ocho semanas terminás con una aplicación funcionando —interfaz, servidor y datos— y vas a tener que explicar cómo la dirigiste. No vas a escribir la mayor parte del código. El trabajo se corrió de lugar: la IA implementa; vos decidís y verificás.

  • Docente: Enzo Pacilio
  • Año: 2026
  • Modalidad: 8 clases de 3 horas

Qué es este curso

No es un curso de programación ni un taller de trucos de prompt. Es un curso sobre dirigir: nombrar las piezas del software, especificar antes de que se escriba una línea, y auditar lo que vuelve. El rol tiene nombre: supervisor.

El recorrido tiene tres movimientos. Primero, entender la herramienta (cómo predice un token, por qué alucina, qué es la ventana de contexto). Segundo, aprender a nombrar frontend y backend. Tercero, dirigir a un agente que ya no solo escribe: actúa sobre tu proyecto.

Al final vas a poder abrir un proyecto que no escribiste, entender su estructura, pedirle un cambio concreto a un agente y darte cuenta de si lo que volvió sirve. Las herramientas cambian; el criterio, no.

Tres movimientos

1 · Entender

La herramienta

Tokens, predicción estocástica, pre-training, post-training, alucinaciones y límites de cómputo por token.

2 · Nombrar

Frontend y backend

HTML semántico, CSS, estado y eventos. HTTP, REST, datos, errores y contratos OpenAPI.

3 · Dirigir

El agente

Loop pensar → actuar → observar, runtime, plugins, spec-driven development y MCP.

Objetivos

  • Desarrollar intuición sobre modelos de lenguaje: tokenización, predicción estocástica, pre-training y post-training, RLHF, alucinaciones y límites del razonamiento.
  • Conocer el mapa del software (frontend, backend, APIs y datos) para especificar, dirigir y auditar lo que genera la IA. Contratos OpenAPI. Git y GitHub Flow.
  • Operar entornos agénticos: el loop del agente, la ventana de contexto como recurso finito, memoria, reglas, permisos, skills, sub-agentes y modo plan.
  • Extender el entorno: plugins, spec-driven development y Model Context Protocol.
  • Aplicar pensamiento computacional: descomponer problemas en especificaciones y planes verificables, sosteniendo el rol de supervisor arquitectónico.

Unidades

Seis unidades temáticas. No coinciden una a una con las ocho clases: la unidad 4 ocupa dos encuentros y la última clase es el Demo Day.

Unidad 1 — Funcionamiento de LLMs

El átomo del lenguaje (tokens y BPE). Predicción del siguiente token. Pre-training: curación de datos, filtrado, cómputo. Modelos base: autocompletado, in-context learning y cutoff date. Post-training: SFT. Alineación con RLHF. Alucinaciones y mitigación por herramientas. Límites cognitivos y modelos de razonamiento.

Unidad 2 — Arquitectura frontend y dirección de la IA

El trío web: HTML semántico, CSS (caja, layout, tipografía, color, variables) e interactividad (estado, DOM, eventos). Paradigma single-file platform. Cuatro patrones de prompt para UI. Ciclo Architect → Prompter → Reviewer → Tester.

Unidad 3 — Arquitectura backend, datos y contratos

Cliente-servidor y HTTP. REST: recurso, jerarquía, idempotencia. El endpoint como contrato. SQL frente a documentos. Lectura de fallas: 4xx, 5xx, logs y stack traces. OpenAPI y Swagger UI.

Unidad 4 — Fundamentos de desarrollo agéntico y runtime

De una IA que escribe a una que actúa. Loop pensar → actuar → observar. Tools. Ventana de contexto. Modos de falla y rol del supervisor. Memoria persistente, reglas, settings, permisos, skills, sub-agentes y modo plan.

Unidad 5 — Plugins y spec-driven development

De piezas sueltas a paquetes distribuibles. Flujo: diseño por preguntas, plan ejecutable, desarrollo delegado, TDD, revisión, verificación con evidencia y cierre de rama. Git y GitHub Flow. Calidad y testing se trabajan de forma transversal acá.

Unidad 6 — Model Context Protocol (MCP)

Por qué un protocolo y no una API (de N×M a N+M). Host, cliente y servidor. Tres primitives. Discovery dinámico. Transportes Stdio y Streamable HTTP. Cuándo conviene MCP, cuándo no, y qué riesgos se asumen.

Las ocho semanas

Elegí una semana o buscá por tema. El contenido sale del programa y de los hilos de cada carpeta en Material/semanas.

Ninguna semana coincide con ese filtro.

Semana 1 — Funcionamiento de LLMs

Material 00 + 01

Apertura del curso y sondeo. Después, el pipeline completo: internet → filtrado → tokens → entrenamiento → modelo base → SFT → alucinaciones y herramientas → RL y modelos de razonamiento. Fuente: Karpathy, Deep Dive into LLMs like ChatGPT.

Semana 2 — Arquitectura frontend

Material 02

Vocabulario para dirigir interfaz: HTML como sustantivos, CSS (caja, flex/grid, tipografía, variables), estado-DOM-eventos, un solo archivo, y cuatro patrones de prompt. Cierre: actividad grupal Architect → Prompter → Reviewer → Tester.

Semana 3 — Backend, datos y contratos

Material 03

Cliente-servidor, methods y status codes, REST, el endpoint como contrato, relaciones frente a documentos, lectura de fallas, y OpenAPI dictado en vivo con render en Swagger UI.

Semana 4 — De escribir a actuar

Material 04 · parte 1

El agente entra en un loop: pensar → actuar → observar. Tools como manos, ventana de contexto finita, modos de falla y el rol del supervisor. Presentación del entorno agéntico en terminal.

Semana 5 — Configuración del runtime

Material 04 · parte 2

Memoria persistente, reglas por alcance, settings, permisos allow/deny/ask, skills, sub-agentes y modo plan. Cada estudiante expone la idea del trabajo práctico final y recibe devolución de alcance.

Semana 6 — Plugins y spec-driven development

Material 05

Las piezas del runtime se empaquetan en un plugin. Instalación de Superpowers y el flujo: brainstorming, plan, desarrollo con sub-agentes, TDD, review, verificación con evidencia, merge. Git y GitHub Flow.

Semana 7 — Model Context Protocol

Material 06

Más allá del set de tools del host. Protocolo, no API. Arquitectura host/cliente/servidor, tres primitives, discovery dinámico. Demos de transporte local (Stdio) y remoto (Streamable HTTP). Cuándo MCP y qué riesgos.

Semana 8 — Demo Day

Material 08

Exposición del MVP. Defensa del proceso: cómo se especificó, cómo se gestionó el contexto, cómo se detectó y corrigió la deriva del agente. Apropiación tecnológica: explicar, corregir y extender el código generado.

Cómo se aprueba

Tres trabajos prácticos individuales, en un único repositorio público de GitHub, con una carpeta por entrega. Que funcione no alcanza: se evalúa si podés contar el proceso. Eso se llama apropiación.

TP 1

Entrega acotada para practicar lo visto en clase (esta página vive acá).

TP 2

Segunda práctica acotada. Misma forma: carpeta, README-informe, proceso visible.

TP final

Aplicación completa —interfaz, servidor y datos— defendida en el Demo Day.

El README de cada carpeta es el informe: especificación inicial, prompts, manejo de contexto, desvíos y cómo se ejecuta. Desde la clase 6, también spec y plan en disco, commits, ramas y pull requests. El historial no se fabrica la noche anterior.
